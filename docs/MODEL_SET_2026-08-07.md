Verified against the HuggingFace API (`config.json`, safetensors param counts,
`chat_template.jinja`) and the TransformerLens compatibility registry
(`supported_models.json`, generated 2026-07-07, 15,670 models / 143

reviewer liability on its own. But the reason to refresh is **not** credibility —
it is that the current landscape hands us two controlled experiments for free.

## The two free controlled experiments — this is why this set

**1. Qwen3.5-27B vs Qwen3.6-27B — architecture held exactly fixed.**
Verified identical configs: same architecture string, 64 layers, 5120 d_model,
24/4 heads, 17408 d_ff, vocab 248320, 27.8B params. They differ **only in
post-training.** So: *does the refusal direction move under re-alignment when
the architecture is byte-for-byte the same?* That is a publishable result on its
own, and it doubles as a **positive control for our whole apparatus** — if we
cannot detect a difference between two checkpoints that genuinely differ, our
pipeline cannot detect anything, and we learn that before spending the budget.

**2. gemma-4-31B-it (dense) vs gemma-4-26B-A4B-it (MoE, 128 experts).**
Same family, same recipe, same tokenizer, same release date. A controlled
dense-vs-MoE contrast with no confounds.

## The genuinely novel angle

**No published work tests refusal directions on hybrid linear-attention
models.** Qwen3.5/3.6 use 48 linear-attention layers interleaved with 16 full
(`full_attention_interval=4`). Because gated-delta-net-style layers compress
history into a fixed-size recurrent state rather than an explicit KV cache, the
KV-contamination failure mode reported for steering (arXiv:2605.10664) may not
apply the same way. The Qwen3.5 ladder is the natural vehicle for that question.

## What the 2026 literature says about steering on new architectures

**MoE is fine.** *Expert-Aware Refusal Steering* (arXiv:2606.04160, Jun 2026):
plain difference-in-means achieves 65–95% ASR across gpt-oss-20B,
Mixtral-8x7B, OLMoE; expert-aware variants **underperform** it. Refusal in MoE
is "not localized to the MoE feed-forward sublayer." Practical detail worth
stealing: rarely-routed experts give unreliable difference-in-means estimates,
so force an FFN output for all experts on all tokens when computing directions.

**Reasoning models break static steering — and the evidence has a hole we can
fill.** *Beyond a Single Direction* (arXiv:2605.26772, May 2026): steering
compliance is 39% with CoT held fixed, 70% with CoT removed, 94% with CoT
regenerated under steering. Refusal is jointly encoded in the residual stream
*and* the CoT text. **But they test exactly one model (DeepSeek-R1-Distill-
Llama-8B) and run no non-reasoning control.** Qwen3.5/3.6 have a
within-checkpoint thinking toggle, which is precisely the control they omitted.

**Protocol that follows:** fit and evaluate every direction in **non-thinking
mode** as the primary condition — this keeps us comparable to Arditi et al. and
to the 2025 baseline — and report thinking mode as secondary. **Never mix the
two when fitting a direction:** the `<think>` block shifts token positions and
contaminates the contrast set.

## Bonus: official SAEs at every ladder rung

Alibaba ships **Qwen-Scope** — residual-stream SAEs for the Qwen3.5 series
(`Qwen/SAE-Res-Qwen3.5-27B-W80K-L0_50` and siblings at 9B/2B/35B-A3B, per-layer
`layerN.sae.pt`, arXiv:2605.11887). Building the ladder on Qwen3.5 means we can
cross-check difference-in-means directions against SAE features at every rung
with no SAE training. **License is a custom Qwen license, not Apache — check it
before depending on it.**

## Implementation gotchas (verified, will bite)

1. **Shapes are nested.** Qwen3.5/3.6 use `Qwen3_5ForConditionalGeneration` (a
   multimodal wrapper) with a `text_config` block. Read
   `config.text_config.num_hidden_layers`, **not** `config.num_hidden_layers`,
   and reach the LM through `.language_model`. Gemma 4 is the same
   (`Gemma4ForConditionalGeneration`, also has `text_config`).
   **This interacts directly with our shape-assertion rule** — assert against
   the nested values or the guard passes on the wrong numbers.
2. **`gated_hooks_fire` fails on every verified Qwen3.5 checkpoint** in TL
   parity phases 2 and 3 (P2 92.3%, P3 94.7%). The gated linear-attention hooks
   do not fire in HookedTransformer-compat mode. Residual-stream hooks are a
   different code path and *should* be unaffected — but **write an assertion
   comparing `hook_resid_post` against a raw HF forward hook before trusting a
   single number.** Do not take this on faith.
3. **Pin `transformer-lens==3.6.0`.** 4.0.0b1 (2026-07-21) is beta and
   introduces a vLLM-backed driver system; do not let `pip install -U` pull it
   mid-experiment.
4. **Don't be scared off gemma-4-31B by its P4=55.1 registry score.** The
   registry note attributes it to the benchmark feeding raw prompts without the
   Gemma chat template; E2B/E4B on the same adapter score 95–96.
5. **Avoid 4-bit for 70B-class.** Quantization perturbs the residual stream we
   are measuring, and arXiv:2606.10154 argues quantization changes safety
   behavior independently of quality.

## Watch: Qwen 3.8 (expected ~week of Aug 10, 2026)

Team report: Qwen 3.8 is expected next week and is likely to include a 27B.
**Unverified — confirm on HF before acting.**

If it lands with a 27B dense checkpoint, it is a straight swap-in for the
Qwen3.6-27B slot and it *strengthens* the design rather than disrupting it:
Qwen3.5-27B / 3.6-27B / 3.8-27B would give a **three-point post-training series
on a fixed architecture** — how does the refusal direction move across
successive alignment generations with the weights' shape held constant? That is
a better version of the controlled experiment we already have.

Adoption rules, so a release does not derail the sprint:

1. **Verify the config is actually identical** before claiming a controlled
   comparison — same `architectures` string, layers, d_model, heads, d_ff,
   vocab. Qwen3.6-27B reuses `Qwen3_5ForConditionalGeneration`; a new
   generation may not, and if the architecture changed, the comparison is no
   longer controlled and the claim must be dropped.
2. **Check TransformerLens adapter coverage.** No `qwen3_6.py` exists because
   3.6 declares the 3.5 architecture. If 3.8 declares something new, there may
   be no adapter and no verified parity — budget time or fall back to nnsight.
3. **Do not swap mid-experiment.** Add it as an extra arm, or take it in a
   later wave. Changing a model after directions are fitted invalidates the
   comparison, and re-fitting costs the budget twice.
4. **The reasoning-mode switch may change again.** Qwen3.6 already dropped the
   `/think` `/nothink` soft switch that Qwen3 had, leaving only
   `chat_template_kwargs`. Read the actual `chat_template.jinja`, do not assume.

Default if it slips or the config diverges: ship with the verified set above.
The three-point series is an upgrade, not a dependency.

## Rejected, with reasons

- **There is no Llama 5.** Several secondary sources claim an April 2026
  release; the `meta-llama` HF org has shipped no LLM since Llama 4 (Apr 2025),
  and Meta's 2026 flagship is closed-weight. **Do not build a Llama arm.**
- **Llama 4** — gated, restricted license, and its TL adapter has never been
  verified against a checkpoint.
- **DeepSeek V4 (291B+), GLM-5 (~750B), Kimi K3 (2.78T), MiniMax M3 (427B)** —
  all far over budget; no Kimi or MiniMax-M3 adapter exists at all.
- **`allenai/Olmo-3-7B-Instruct`** — TL status **FAILED** (real parity failure,
  P2 64.3 / P3 75.0). If we want an OLMo arm, use `Olmo-3.1-32B-Instruct`
  (skipped on size only, i.e. untested rather than known-bad) — and its
  `-Think` twin is the best-controlled reasoning-vs-not pair available anywhere.
- **Phi** — nothing since Phi-4 (Jan 2026); not competitive for a 2026 set.
