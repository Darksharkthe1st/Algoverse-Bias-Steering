# Dashboard update

The dashboard (`dashboard/index.html`) is the team's shared "active project
state" page. It is generated by `scripts/build_dashboard.py` from
**hand-maintained narrative constants** at the top of that file, plus two
results tables rendered live from committed CSVs. This skill keeps the
constants honest. Anyone on the team can run it from their own machine —
changes ship as a PR; CI rebuilds the HTML on merge.

## Procedure

1. **Collect what changed since the dashboard's last truth.** Check, in order:
   - `git log --oneline -20 main` and recently merged PRs (`gh pr list --state
     merged --limit 10`) — new results, merged experiment branches.
   - New CSVs/pickles under `experiments/` (the `Log_N_*` convention). Note the
     judge version for any judged number — judge v1 (2025 binary) numbers are
     provisional and must be labeled as such.
   - `PAPER_FRAMING.md` and `HANDOFF_*.md` for thesis/priority changes.
   - The venue deadline: verify against the venue page before repeating it.
2. **Edit only the narrative constants** in `scripts/build_dashboard.py`:
   `TAGLINE`, `OVERVIEW`, `RESEARCH_Q`, `PHASE`, `RUNS`, `DECISIONS`, `TASKS`,
   `HOW_WE_WORK`, `MILESTONES`, `PATH_TO_SUBMISSION`, `LINKS`, `FRONTIER`,
   `BULLETPROOFING`. Rules:
   - Every number traces to a committed `experiments/` artifact; put the path
     in the PR body.
   - States are `done | running | queued` (RUNS), `active | blocked | queued |
     done` (TASKS), `done | now | next | then` (milestones/path). Don't invent
     new states — the CSS won't render them.
   - Follow `PAPER_FRAMING.md` for any wording about claims or framing.
   - Keep entries one-to-two lines; the dashboard is a glance surface.
3. **Rebuild:** `python3 scripts/build_dashboard.py --out dashboard/index.html`
   (pure stdlib, any Python ≥3.10; run from repo root so the CSV paths resolve).
4. **Ship as a PR** on a `dashboard/<topic>` branch with the built
   `dashboard/index.html` included. Never push main directly.

## Editing the frontier/reading-list section

`FRONTIER` entries are `(action, title_with_arxiv_id, one_line_relevance)`
where action ∈ `must-cite | nice | watch`. Add papers with a one-line reason
tied to OUR claims (not a generic summary). When a paper changes our framing,
update `PAPER_FRAMING.md` in the same PR — the dashboard mirrors doctrine, it
doesn't define it.
